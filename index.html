CubeZ

A toolkit that edits, captions and publishes short-form video for a single creator's own accounts. It runs on the creator's own machine, keeps their footage and credentials there, and posts only what they tell it to post.

What it does

The parts

Clip and caption

CubeZ cuts long recordings into short vertical clips, adds captions and a watermark, and writes a title, description and hashtags for each one. Everything happens on the operator's own computer; there is no CubeZ cloud, and no footage is uploaded anywhere except to the platforms the operator has connected.

Publish to the operator's own accounts

When a new short-form video is published to the operator's YouTube channel, CubeZ posts it onward to the operator's other accounts — as an upload to TikTok, Facebook and Instagram, and as a link on Discord, Bluesky and Mastodon.

It only ever posts to accounts the operator owns and has personally authorised. There is one operator, one set of accounts, and no other users. CubeZ does not publish on behalf of anyone else, does not accept content from third parties, and has no sign-up, no user accounts and no shared service of any kind.

What the TikTok integration is used for

CubeZ uses TikTok's Content Posting API for exactly one thing: uploading the operator's own newly published short-form video to the operator's own TikTok account, with a caption built from the video's own title. The upload is a direct file upload of a video the operator created and has already published themselves.

CubeZ uses Login Kit once, so the operator can authorise their own account. It reads nothing but the basic profile needed to confirm which account is connected. It does not read other users' content, does not browse or scrape TikTok, and does not post comments, messages or reactions.

The two scopes CubeZ asks for, and where each one is used

  • user.info.basic — called once, immediately after sign-in, so CubeZ can display which TikTok account is connected. It reads the open id and display name of the operator's own account and nothing else.
  • video.publish — called when the operator's new short-form video is ready. CubeZ uploads that video file to the operator's own account through the Content Posting API's FILE_UPLOAD flow, with a caption built from the video's own title.

The app's TikTok registration also lists video.upload, the draft-posting scope. TikTok's Content Posting API includes it by default and the developer portal offers no way to remove it. CubeZ does not use it: its sign-in request asks only for user.info.basic and video.publish, and it never calls the draft inbox endpoint. Beyond the two calls above, CubeZ makes no TikTok API call of any kind.

How the account is connected

  1. The operator runs python -m poster auth-tiktok in their own copy of CubeZ, which opens TikTok's authorisation page.
  2. They approve the request on TikTok's own consent screen.
  3. TikTok returns them to this site's callback page, which displays the one-time authorisation code and sends it nowhere.
  4. They paste the code back into CubeZ, which exchanges it with TikTok for an access token, reads the account's display name with user.info.basic to confirm the right account is connected, and saves the tokens to a file on their own machine.

Announcements

Alongside publishing, CubeZ posts a notice to the operator's own Discord server when there is a new video, when the operator goes live on Twitch, and when free games or free creator assets appear on public storefronts.

Data and credentials

Access tokens are stored by the operator, on the operator's own infrastructure, and are used only to post to the accounts those tokens belong to. Nothing is sold, shared or sent to any third party. The full detail is in the Privacy Policy, and the terms of use are in the Terms of Service.
